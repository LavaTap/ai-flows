## name: product-analysis description: 围绕具体产品、产品想法或存量方案，产出用于产品进入、定位、竞争策略、上市路径、能力建设与路线图决策的证据型分析报告。适用于“值不值得做或发布”“进入哪个细分”“目标用户和市场是否成立”“竞品为何这样设计”“该借鉴、差异化或放弃什么”“核心能力与 Roadmap 怎么定”“如何调整已有产品”等请求，也适用于将用户研究、市场信息、竞品实测、内部资料和业务约束整合为决策建议。支持 0→1、存量产品调整、竞品专项与组合分析；默认交付为可独立阅读的飞书云文档，并用正文内 HTML5 block 呈现必要的产品定位图或能力路线图。不用于只需罗列功能、直接撰写实施 PRD，或在缺少依据时给出确定性预测的任务。

# 产品分析：证据型产品决策报告

> 把“我们该不该做、做给谁、凭什么赢、先做什么”这类问题，变成一份有依据、可被反驳、能直接进决策会的报告。

## 0. 技能定位

本技能产出的不是资料汇编，而是**决策支持文档**。唯一验收标准：读者读完能当场做出一个具体选择，并知道依据是什么、还有哪些没验证、下一步怎么验证。

一句话公式：

`决策报告 = 明确的待选选项 + 会改变选择的证据 + 明确的选择与放弃 + 可执行的验证下一步`

三条底线：

1. **有选项**——报告必须是在几个选项之间做选择，不是描述一个东西。
2. **有依据**——每个关键结论都能指到证据编号；无证据的判断必须标为假设。
3. **有放弃**——必须写清“不做什么”，否则不算完成。

## 1. 适用与不适用

### 1.1 适用（出现以下任一即触发）

| 用户说法 | 背后的决策问题 |
| --- | --- |
| 这个产品/想法值不值得做、值不值得发布 | Go / No-Go / 缓做 |
| 应该进入哪个细分市场 | 滩头市场选择 |
| 目标用户和市场是否成立 | 需求真实性与付费意愿 |
| 竞品为什么这么设计 | 设计意图反推、可借鉴性 |
| 该借鉴、差异化还是放弃 | 竞争策略取向 |
| 核心能力与 Roadmap 怎么定 | 能力建设与节奏 |
| 已有产品该怎么调整 | 存量变更方向 |

### 1.2 不适用 / 应交出去

- 只需罗列功能、做竞品功能对照表 → 本技能不适用。
- 方向已定，要写实施级 PRD / 需求文档 → 交给产品经理技能。
- 缺依据却要求“给出确定的市场规模/销量预测” → 只能给区间 + 假设前提 + 置信度，并显式标注为预测。
- 纯翻译、转写、校对、格式转换 → 不做。

### 1.3 四类分析模式（Phase 0 先判定，后续流程按模式裁剪）

| 模式 | 起点 | 核心问题 | 主要产出 |
| --- | --- | --- | --- |
| 0→1 机会评估 | 想法 / 空白市场 | 值不值得做 | Go/No-Go + 最小验证 |
| 存量产品调整 | 已有产品与数据 | 改什么、怎么改 | 诊断 + 变更路径 |
| 竞品专项 | 竞品样本 | 它为何这样设计 | 设计意图 + 借鉴/放弃清单 |
| 组合分析 | 多条产品线/多个选项 | 资源往哪压 | 排序 + 取舍 |

## 2. 工作原则（六条，违反即返工）

- **P1 以决策问题组织分析。** 先写清“要在哪几个选项之间选”，再去找证据。禁止按框架目录填章节。
- **P2 以真实现状为起点。** 分析存量产品、内部方案或已有文档时，先读取现状、数据、反馈和约束，再提出变化。
- **P3 证据分级、结论可溯源。** 每个关键结论后挂证据编号（见 §5），无证据的判断标注为“假设”。
- **P4 结论先行、可被反驳。** 开篇一页决策摘要给出选择；正文用于支撑结论并主动暴露反例。
- **P5 明确“不做什么”。** 报告必须包含放弃项及其理由。
- **P6 区分事实 / 推断 / 预测。** 三类内容用不同标记；预测必须给假设前提与置信度。

## 3. 执行流程（八个阶段）

### Phase 0 任务定界（必做，不可跳过）

**目标**：把模糊请求收敛成一个可回答的决策问题。

**动作**：

1. 判定 §1.3 中的分析模式。
2. 填写「决策问题卡」。
3. 列出待选选项（≥2 个，且必须包含“不做”这一选项）。
4. 明确决策者、决策时间点、不可逾越的约束（预算/合规/技术/时间）。
5. 明确“什么证据会改变选择”。

**决策问题卡模板**：

`决策者：`\
`决策截止时间：`\
`要在这些选项之间选：A / B / C / 不做`\
`现状约束（不可动）：`\
`必须回答的问题：`\
`什么证据会翻转结论：`\
`本次不回答的问题（划边界）：`

**完成判据**：能用一句话复述“为谁、在什么约束下、在哪些选项之间选”。

---

### Phase 1 现状摄入

**目标**：建立事实基线。

**动作**：

1. 列出材料清单并逐份读取真实内容：云文档、附件、截图、脑图、表格、访谈记录、后台数据、客服工单、销售与客户评论、旧产物。
2. 抽取事实：用户、场景、量级、价格、渠道、转化/留存/复购、成本结构、已知约束、已定决定。
3. 单列“数据缺口”，**不要用印象填补**。

**输出**：事实基线表 + 数据缺口表。 **完成判据**：每条基线事实都能指到来源。

---

### Phase 2 决策问题树与假设

**动作**：

1. 把决策问题拆成 3–7 个必须先回答的子问题。
2. 每个子问题写出「当前假设」与「反假设」（假设不成立会怎样）。
3. 标注「关键不确定项」：一旦不成立，结论翻转。

**输出**：问题树（缩进列表即可）+ 关键不确定项清单。 **完成判据**：关键不确定项数量可控（通常 2–4 个），且都能被证据检验。

---

### Phase 3 证据采集与验证

**动作**：

1. 按 §5.2 清单分头采集：内部资料 / 外部市场 / 竞品实测 / 用户声音。
2. 每条证据登记：来源、时间、口径、等级（A/B/C/D）。
3. 对关键不确定项优先取证；无法取证的，明确标为假设。

**输出**：证据台账（表格）。 **完成判据**：所有关键不确定项要么有 A/B 级证据，要么明确标为假设。

---

### Phase 4 分析

**动作**：

1. 按 §4 索引，为每个子问题选**最少必要**的框架（通常 3–5 个，不堆砌）。
2. 每个框架产出：一句话结论 + 支撑证据编号 + 反例/边界条件。
3. 交叉验证：用户声音 vs 行为数据 vs 竞品事实 vs 商业模型是否自洽。

**输出**：分问题分析结论。 **完成判据**：每个子问题都有结论；结论之间若矛盾，已显式处理（给出优先依据或转为待验证假设）。

---

### Phase 5 结论与建议

**动作**：

1. 给出明确选择：推荐选项 + 次选 + 明确放弃项，各附一句话理由与置信度。
2. 写出“若此结论错，最可能错在哪”。
3. 给出下一步验证：验证哪个假设、用什么最小成本方法、成功/失败判据、时间盒。

**输出**：决策摘要（1 页）+ 验证计划。

---

### Phase 6 成稿与可视化

**动作**：

1. 按 §6.1 结构成文，结论前置。
2. 需要时插入 HTML5 block：产品定位图、能力路线图（§6.2 模板）。
3. 补齐术语表与证据附录。

**完成判据**：一个没参与分析的人能独立读懂并复述结论。

---

### Phase 7 质量门禁

**动作**：逐条过 §7 清单，未过项返工。 **完成判据**：清单全绿。

---

### Phase 8 交付与迭代

- 默认交付：可独立阅读的飞书云文档（结构见 §6.1）。
- 在文末标注「下次复核触发条件」，例如：竞品大版本发布、试点数据出结果、政策变化、成本结构变化。

## 4. 分析框架索引（按决策问题选，不是全用）

| 决策问题 | 首选框架 | 最小必要证据 | 常见陷阱 |
| --- | --- | --- | --- |
| 值不值得做 | JTBD + 机会评估（量级/时机/战略契合/单位经济） | 问题真实存在 + 至少一个付费或强替代信号 | 用 TAM 大数掩盖付费意愿缺失 |
| 进入哪个细分 | 细分矩阵 + 滩头市场评分 | 各细分痛点强度、触达成本、竞争密度 | 选最大而非最易赢的细分 |
| 市场/用户是否成立 | ICP 画像 + 需求证据强度 + 替代方案分析 | 一手访谈 + 行为数据 | 把“感兴趣”当“会付费” |
| 竞品为何这样设计 | 设计意图反推（能力-约束-商业模型三角）+ 竞品拆解表 | 可复现功能实测 + 定价/渠道信息 | 只抄功能不抄约束 |
| 借鉴/差异化/放弃 | 定位法（替代方案-独特属性-价值-匹配人群）+ 护城河分析 | 竞品短板 + 自身独有能力 | 差异化点对用户无价值 |
| 能力与 Roadmap | 能力差距分析 + 能力分层（表层功能/中层机制/底层资产） | 目标能力 vs 现状能力清单 | 把功能当能力 |
| 存量产品调整 | 现状诊断（数据-反馈-约束）+ 变更影响面 | 产品数据 + 用户反馈 + 技术约束 | 忽略迁移与兼容成本 |
| 组合取舍 | 组合排序（战略契合 × 回报 × 确定性 ÷ 投入） | 各选项的投入与预期产出 | 平均用力、不做取舍 |

**框架使用纪律**：每个框架必须落一句“所以呢”。落不出结论，就换框架或删掉该框架。

## 5. 证据体系

### 5.1 证据分级

| 等级 | 定义 | 例子 | 使用限制 |
| --- | --- | --- | --- |
| A | 一手、可核验、与决策直接相关 | 自有后台数据、财务、合同、真实成交、可复现实测 | 可作为结论主证据 |
| B | 一手但样本有限，或高质量二手 | 用户访谈、问卷、可复现公开数据 | 需交叉验证 |
| C | 二手/媒体/第三方报告 | 行业报告、媒体报道 | 仅作背景与旁证 |
| D | 推测/类比 | 专家直觉、类比他行业 | 必须显式标注，不得作为唯一依据 |

### 5.2 采集清单

- **内部**：产品后台数据、用户反馈/工单、销售与客户沟通记录、财务与成本、技术约束与排期、既有方案与旧文档。
- **外部**：市场规模与增速、政策与合规、渠道与流量成本、技术可行性（开源/供应商）、上下游生态。
- **竞品**：可复现功能实测、定价与套餐、获客渠道、用户评价（应用商店/社区/差评区）、融资与动向。
- **用户**：至少 5 个目标用户的一手声音，覆盖“重度使用 / 流失 / 从未使用”三类。

### 5.3 证据冲突处理

1. 先查口径：时间、样本、定义是否一致。
2. 口径一致仍冲突 → 以 A 级优先，并在报告中显式呈现冲突，而非隐藏。
3. 无法消解 → 转成待验证假设，写入验证计划。

### 5.4 引用规范

正文用 `[E12]` 编号；附录给完整出处：来源名称 / 时间 / 口径 / 等级 / 链接或位置。**禁止出现无编号、无来源的数字。**

## 6. 交付规范

### 6.1 飞书云文档结构（默认）

`1. 决策摘要（1 页）—— 推荐选择 / 次选 / 明确放弃 / 一句话理由 / 置信度`\
`2. 待选选项与判据 —— 选项定义、评估维度、权重`\
`3. 现状基线 —— 事实基线表、数据缺口`\
`4. 分析（按子问题）—— 每个子问题：结论 + 证据编号 + 反例`\
`5. 建议与路线 —— 选择、放弃、阶段安排`\
`6. 风险与未验证假设 —— 含“若错会错在哪”`\
`7. 验证计划 —— 假设 / 方法 / 判据 / 时间盒 / 负责人`\
`8. 附录 —— 证据台账、术语表、竞品实测记录`

硬性要求：结论前置；每张图表标题即结论；术语首次出现给解释；全文无未标来源的数字。

### 6.3 “可独立阅读”判据

- 无背景的读者能复述：为谁、解决什么、为什么现在、选什么、放弃什么、下一步验证什么。
- 每个数字有来源，每个结论有证据编号。
- 图表离开正文也能读懂。

## 7. 质量门禁（交付前逐条核对）

 1. 有明确的待选选项，且包含“不做”。
 2. 有决策摘要，且结论前置。
 3. 每个关键结论挂证据编号。
 4. 无 A/B 级证据的关键判断已标为“假设”。
 5. 有明确的放弃项与理由。
 6. 预测类内容给出假设前提与置信度。
 7. 竞品结论基于实测/可复现证据，而非印象。
 8. 存量分析读取了真实现状（数据 + 反馈 + 约束）。
 9. 框架未堆砌，每个框架都落了“所以呢”。
10. 有验证计划（假设 / 方法 / 判据 / 时间盒）。
11. 有“若结论错会错在哪”。
12. 术语有解释，图表自解释。
13. 数字均有来源与口径。
14. 报告可被没参与分析的人独立读懂。
15. 未越界做确定性预测或替用户拍板。

## 8. 常见失败模式

| 失败模式 | 表现 | 纠正 |
| --- | --- | --- |
| 资料汇编 | 大段行业背景，读完不知选什么 | 回到 Phase 0 决策问题卡 |
| 框架堆砌 | 每章一个框架，无结论 | 每个框架落“所以呢”，落不出就删 |
| 结论后置 | 读完不知推荐什么 | 决策摘要前置 |
| 无放弃项 | 什么都想做 | 强制写放弃项及理由 |
| 预测伪装 | 用肯定句给未来数字 | 改区间 + 假设 + 置信度 |
| 抄功能不抄约束 | 竞品有什么就抄什么 | 反推设计意图与约束 |
| 忽略迁移成本 | 存量改造只谈新方案 | 补影响面与迁移路径 |

## 9. 与相邻能力的衔接

- 需要写实施级 PRD、用户故事、验收标准 → 转产品经理技能。
- 需要做汇报材料 / 视觉化总结页 → 转可视化产出能力。
- 需要外部实时数据 → 先采集证据再分析，不得凭记忆补数。
