# 游戏策划案分析与撰写框架

本文件包含游戏策划案分析的标准化框架，仅在执行图片玩法分析时参考使用。

---

## 一、适用场景与边界
### 1.1 适用场景
- 对已有游戏策划案做结构、逻辑、落地性的全面分析与优化建议
- 从零撰写功能系统、核心战斗机制、社交运营体系等类型的策划案
- 匹配二次元、FPS、魂系动作、卡牌、MMO等不同品类的设计风格与文档粒度
- 基于现有策划案进行扩展、补全、反推设计逻辑

### 1.2 不适用场景
- 不输出可直接编译运行的程序代码
- 不提供精确的数值平衡计算与经济系统推演
- 不替代专业美术原画、技术架构、法律合规类专项评审

---

## 二、核心工作流程
### 2.1 策划案分析流程
1. **基础信息识别**：提取游戏品类、策划案类型、核心设计目标
2. **结构完整性校验**：对照标准框架排查缺失模块
3. **逻辑闭环验证**：梳理玩家行为流、异常分支、规则自洽性
4. **品类适配评估**：判断设计风格、深度、包装是否匹配对应品类
5. **落地性分析**：评估程序、美术、运营成本与潜在风险
6. **输出结论**：总结优势、问题点与优化建议

### 2.2 策划案撰写流程
1. **需求拆解**：明确系统定位、设计目标、目标用户与业务指标
2. **品类匹配**：根据游戏类型确定文档风格、设计侧重与粒度
3. **框架搭建**：选择对应类型的策划案模板，搭建章节结构
4. **细节填充**：补充界面规则、逻辑流程、异常处理、配套需求
5. **闭环校验**：按自检清单排查逻辑漏洞与缺失项
6. **优化输出**：形成结构清晰、规则明确的可执行策划文档

## 三、策划案分析框架
### 3.1 基础信息维度
| 分析项 | 核查要点 |
|--------|----------|
| 游戏品类 | 二次元/射击/动作/卡牌/MMO/模拟经营等，匹配对应设计范式 |
| 案型分类 | 功能系统类 / 核心机制类 / 社交运营类 / 关卡玩法类 |
| 系统定位 | 基础工具型 / 玩法核心型 / 留存拉新型 / 付费转化型 |
| 设计目标 | 是否明确用户价值、业务目标（如提升留存、优化体验、完善循环） |

### 3.2 结构完整性维度
对照标准策划案结构，核查缺失模块：
1. **设计说明层**：系统定位、设计目的、用户体验目标
2. **系统概述层**：整体功能介绍、系统架构思维导图、用户体验流程图
3. **详细设计层**：系统入口、主界面规则、核心功能模块、交互逻辑、异常处理
4. **配套需求层**：程序开发需求、美术资源需求、策划配置需求、测试用例需求
5. **落地验证层**：预期效果、核心观测指标、风险预估与应对方案

### 3.3 逻辑闭环维度
- **主流程通顺性**：玩家从入口到操作完成的全路径是否无断点
- **异常分支覆盖**：容量上限、网络异常、操作取消、条件不满足等边界场景是否有处理规则
- **规则自洽性**：奖励、惩罚、触发、冷却等规则是否前后一致，无矛盾
- **数值合理性**：阈值、倍率、冷却时间等数值是否有明确的设计依据与平衡逻辑

### 3.4 品类适配维度
- 世界观包装、文案话术是否贴合游戏IP与用户调性
- 系统深度、操作复杂度是否匹配品类核心用户习惯
- 付费点、社交点、养成线设计是否符合品类商业范式

### 3.5 落地性维度
- 技术实现成本：是否需要底层架构改造，还是基于现有框架扩展
- 美术资源量级：界面、动画、特效等资源需求是否在项目产能范围内
- 运营维护成本：是否需要长期人工配置，是否支持自动化配置
- 风险防御：是否覆盖生态失衡、用户劝退、技术故障等潜在风险

## 四、分品类策划案风格适配
### 4.1 二次元动作/角色扮演类（代表：《崩坏3》）
- **风格特点**：强世界观人设包装，用户体验优先，UI细节粒度极细，文案注重代入感
- **设计侧重**：界面视觉规范、角色IP感贯穿、操作反馈细腻、福利与活动包装
- **典型模块**：邮件系统、签到福利、角色养成、活动剧情、背包仓库
- **撰写要求**：
  - 系统文案、发件人、话术需贴合游戏角色人设
  - 界面需标注字号、色值、布局参数、状态变化
  - 明确不同状态（未读/已读、未领取/已领取）的视觉反馈
  - 覆盖容量上限、过期清理等异常场景的处理规则

### 4.2 FPS战术竞技类（代表：《三角洲行动》）
- **风格特点**：目标导向强，重用户留存与社交生态，分层设计清晰，逻辑严谨
- **设计侧重**：用户分层驱动、数据指标导向、风险防御完备、灰度验证路径
- **典型模块**：军团/公会系统、排位赛季、战令通行证、匹配机制、排行榜
- **撰写要求**：
  - 明确核心业务指标与效果验证方案
  - 区分休闲、活跃、硬核不同层级用户的设计边界
  - 包含生态风险防御策略（如寡头垄断、社交压力、僵尸组织）
  - 设计分阶段上线节奏与灰度验证方法

### 4.3 魂系/动作核心机制类
- **风格特点**：机制优先，逻辑抽象度高，注重多系统间的关联耦合，强调取舍设计
- **设计侧重**：核心战斗循环、受击/技能/养成的联动关系、风险与收益的权衡
- **典型模块**：技能系统、受击判定、成长系统、战斗资源循环
- **撰写要求**：
  - 绘制系统关系图，明确各模块的交互逻辑
  - 拆解机制的触发条件、阈值、冷却、优先级
  - 标注待验证的数值与设计问题，明确迭代方向
  - 突出"代价-成长""风险-收益"的核心设计逻辑

### 4.4 卡牌策略类
- **风格特点**：重养成循环与付费设计，规则清晰，组合逻辑明确
- **设计侧重**：卡组构筑、抽卡机制、养成线深度、对战平衡
- **撰写要求**：明确卡牌稀有度与获取途径；标注技能触发优先级；覆盖养成各阶段的体验节奏

### 4.5 MMO大世界类
- **风格特点**：系统庞杂，社交属性重，长线运营导向
- **设计侧重**：公会体系、副本组队、交易行、阵营对抗、日常循环
- **撰写要求**：区分不同玩家层级的内容供给；明确社交关系沉淀路径；考虑长期版本迭代空间

## 五、策划案撰写模板
### 5.1 通用标准模板
```markdown
# 《游戏名称》XX系统策划案
## 文档历史
| 版本 | 时间 | 作者 | 内容说明 |
|------|------|------|----------|
| V1.0 |      |      | 初稿完成 |

## 一、设计说明
1. 系统定位
2. 设计目标
3. 用户价值

## 二、系统概述
1. 系统核心功能简介
2. 系统架构/思维导图
3. 用户体验主流程图

## 三、详细设计
1. 系统入口与展示规则
2. 主界面信息说明
3. 核心功能模块（分模块拆解：界面信息+逻辑规则+异常处理）
4. 交互流程与状态变化

## 四、配套需求
1. 程序开发需求
2. 美术资源需求
3. 策划配置需求
4. 测试用例需求

## 五、落地与验证
1. 预期效果
2. 核心观测指标
3. 风险预估与应对方案
```

### 5.2 三类专项模板变体
#### （1）功能系统类（邮件、背包、设置等）
- 强化：界面细节标注、异常逻辑分支、容量/上限规则、状态反馈
- 简化：长期生态设计、业务指标拆解

#### （2）核心机制类（战斗、技能、成长等）
- 强化：系统关联图、触发阈值、机制循环逻辑、待验证问题清单
- 简化：美术UI细节、运营配置规则

#### （3）社交运营类（军团、赛季、活动等）
- 强化：用户分层驱动模型、留存指标、风险防御、灰度上线方案
- 简化：单步交互细节、单条文案规范

## 六、质量自检清单
输出策划案前必须逐项校验：
1. □ 明确了系统定位与核心设计目标，无模糊表述
2. □ 玩家主操作流程完整，覆盖正常路径与关键异常分支
3. □ 所有规则逻辑自洽，无前后矛盾与定义冲突
4. □ 文档风格、粒度、侧重点匹配对应游戏品类
5. □ 清晰标注了程序、美术、测试等跨岗位配合需求
6. □ 包含了潜在风险与对应的应对方案
7. □ 可量化目标明确，有对应的效果验证方式
8. □ 术语统一，无歧义表述，符合项目内通用规范
