# ai-flows 能力目录与路由说明

## 一、这是什么

`ai-flows` 是一个按“意图路由”的技能包：它本身不直接干活，而是根据你提出的需求，把你导向对应的业务文档，再由业务文档指导具体执行。

因此，使用它的正确方式是——**先明确你要做什么**，然后它会只读取与该意图匹配的业务文档，避免无关内容干扰。

## 二、能力总览

当前 ai-flows 覆盖三类业务能力：

| 能力 | 适用场景 / 触发词 | 对应业务文档 | 配套脚本 |
|---|---|---|---|
| 仓库初始化与密钥检查 | 初始化仓库、接入评审、装 ai-review、给仓库配评审、检查/重配模型密钥、私有仓库推送凭据 | `references/repository-manager/init.md` | `init-repo.mjs`、`check-key.mjs`、`check-remote-auth.mjs` |
| Python 代码评审 | 代码评审、按规范评审代码、Python 规范检查 | `references/reviewers/CODE-REVIEW.MD` | — |
| ai-review 评审链用法 | 跑评审、起报告服务、起平台、装 hook、ai-review CLI 用法、评审输出规范化 | `references/ai-flows/review-chain.md` | `normalize-review.mjs` |

## 三、各能力说明

### 1. 仓库初始化与密钥检查

面向“把评审能力接入某个仓库”的场景，主要处理：

- 初始化仓库、接入评审流程
- 安装 ai-review 相关配置
- 为仓库配置评审
- 检查 / 重新配置模型密钥
- 私有仓库的推送凭据检查

配套脚本（位于 `<skill-dir>/scripts/`）：

- `init-repo.mjs`：拷贝 config 并安装 pre-push hook
- `check-key.mjs`：校验模型密钥有效性
- `check-remote-auth.mjs`：推送前置检查（远端认证 + 凭据泄露）

### 2. Python 代码评审

面向“对代码按规范做评审”的场景，主要处理：

- 代码评审
- 按规范评审代码
- Python 规范检查

该业务文档内部可能再指向规则子文档（如 `references/reviewers/` 下的规则文件），由业务文档自行决定是否下钻读取。

### 3. ai-review 评审链用法

面向“运行评审、查看报告、使用 CLI”的场景，主要处理：

- 跑评审
- 起报告服务、起平台
- 安装 hook
- ai-review CLI 用法
- 评审输出规范化

配套脚本：

- `normalize-review.mjs`：对评审输出做强制归一（不依赖 prompt）

## 四、使用方式

`<skill-dir>` 指本 `SKILL.md` 所在目录，即 `…/.agents/skills/ai-flows`。

流程如下：

1. 根据你的需求，按路由表确定对应的业务文档。
2. **只**读取该业务文档。
3. 按业务文档的指引执行（脚本一律使用 `<skill-dir>/scripts/` 下的相对路径）。

## 五、目录结构

```
ai-flows/
├── SKILL.md                              # 唯一入口：纯路由
├── references/
│   ├── repository-manager/init.md        # 仓库初始化 + 密钥检查业务
│   ├── reviewers/CODE-REVIEW.MD          # Python 代码评审业务（+ 规则子文档 *.md）
│   └── ai-flows/review-chain.md          # ai-review 评审链用法业务
├── log/code-review/                      # 评审日志（时间戳命名，已 gitignore）
└── scripts/
    ├── init-repo.mjs                     # 拷贝 config + 装 pre-push hook
    ├── check-key.mjs                     # 校验模型密钥有效性
    ├── check-remote-auth.mjs             # 推送前置检查（远端认证 + 凭据泄露）
    └── normalize-review.mjs              # 评审输出强制归一（不靠 prompt）
```

## 六、约束与红线

为保证路由准确、避免越界，ai-flows 遵循以下约束：

- **只读当前意图对应的业务文档**：每轮对话只允许读取与当前意图匹配的相关业务文档，其余文档不打开、不检索、不凭印象引用。
- **按需下钻**：业务文档内部若指向支撑文件，由该业务文档自行决定是否读取。
- **意图不明先问用户**：不会为了“了解全貌”而通读所有业务文档。
- **不越界**：用户没提的业务，不读、不做、不提示。
- 主文档层不写命令细节与业务规则，也不代替业务文档执行操作。
