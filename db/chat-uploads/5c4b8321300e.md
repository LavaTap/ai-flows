# ai-flows 能力总入口与路由说明

## 一、这是什么

`ai-flows` 是一个**按意图路由的技能入口**。它本身不承载业务细节，只做一件事：**判断你想做什么，然后把你指向对应的业务文档**。

所有业务规则、命令细节、脚本用法都写在各自的业务文档里，入口文件（`SKILL.md`）只负责分流。

## 二、目录结构

```
ai-flows/
├── SKILL.md                              # 唯一入口：纯路由，不含业务细节
├── references/
│   ├── repository-manager/init.md        # 仓库初始化 + 密钥检查业务
│   ├── reviewers/CODE-REVIEW.MD          # Python 代码评审业务（+ 规则子文档 *.md）
│   └── ai-flows/review-chain.md          # ai-review 评审链用法业务
├── log/code-review/                      # 评审日志（时间戳命名，已 gitignore）
└── scripts/
    ├── init-repo.mjs                     # 拷贝 config + 装 pre-push hook
    ├── check-key.mjs                     # 校验模型密钥有效性
    ├── check-remote-auth.mjs             # 推送前置检查（远端认证 + 凭据泄露）
    └── normalize-review.mjs              # 评审输出强制归一（不靠 prompt）
```

`<skill-dir>` 指本 `SKILL.md` 所在目录，即 `…/.agents/skills/ai-flows`。所有脚本一律用 `<skill-dir>/scripts/` 下的相对路径调用。

## 四、可处理的业务场景

### 1. 仓库初始化与密钥检查
面向「把 ai-review 接入某个仓库」的场景，覆盖：
- 初始化仓库、接入评审流程
- 安装 ai-review、为仓库配置评审
- 检查 / 重新配置模型密钥
- 私有仓库推送凭据处理

对应脚本：`init-repo.mjs`（拷贝 config + 装 pre-push hook）、`check-key.mjs`（校验模型密钥有效性）、`check-remote-auth.mjs`（推送前置检查：远端认证 + 凭据泄露）。

### 2. Python 代码评审
面向「按规范评审代码」的场景，覆盖：
- 代码评审、按规范评审代码
- Python 规范检查

该业务文档内部可能再指向 `references/reviewers/` 下的规则子文档，由该文档自行决定是否下钻。

### 3. ai-review 评审链用法
面向「运行评审链、起服务」的场景，覆盖：
- 跑评审、起报告服务、起平台
- 装 hook、ai-review CLI 用法
- 评审输出规范化

对应脚本：`normalize-review.mjs`（评审输出强制归一，不依赖 prompt）。

## 五、使用方式

1. 按上表确定当前需求对应的业务文档。
2. **只** Read 该行对应的业务文档。
3. 按业务文档的指引执行，脚本一律用 `<skill-dir>/scripts/` 下的相对路径。

## 六、约束与红线

- **只读当前意图对应的业务文档**：每轮对话只允许读取与当前意图匹配的相关需求业务文档；其余业务文档严禁打开、严禁 `Grep`、严禁凭印象引用。
- **按需下钻**：业务文档内部若再指向支撑文件（如 `references/reviewers/` 下的规则子文档），由该业务文档自己决定是否读取，主文档不管，也不能提前读。
- **意图不明先问用户**，不要为了「了解全貌」把所有业务文档读一遍。
- **不越界**：用户没提的业务，不读、不做、不提示。
- 入口文件不写任何命令细节与业务规则，细节都在业务文档里。
