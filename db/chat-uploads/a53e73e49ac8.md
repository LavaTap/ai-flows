## 二、输入校验与问题说明

### 2.1 输入类型判定

用户提供的链接为 **B站用户空间地址**（`space.bilibili.com/{UID}`），而非视频链接（`bilibili.com/video/{BV号}`）。

本 skill 的 B站采集流程（`references/bilibili-flow.md`）要求以**关键词搜索**方式获取候选视频列表，再经用户确认后进入评论采集。空间地址本身不携带视频信息，无法直接作为采集入口。

### 2.2 空间地址的两种处理路径

**路径 A：将空间视为目标 UP 主，从其投稿中筛选鸣潮相关视频**

- 需调用 B站用户投稿接口（`https://api.bilibili.com/x/space/wbi/arc/search`），该接口受 WBI 签名与风控限制，需携带有效 Cookie（SESSDATA）方可稳定返回。
- 若该 UID 确为鸣潮相关 UP 主，可拉取其投稿列表，按播放量/热度排序取 Top1。
- 若该 UID 并非鸣潮相关 UP 主（如为个人账号、无关账号），则此路径无有效产出。

**路径 B：忽略空间地址，按关键词「鸣潮」执行标准搜索流程**

- 使用 `bridge.py` 的搜索阶段，以「鸣潮」为关键词，综合排序取 Top1 视频。
- 这是本 skill 的标准流程，与用户给出的空间地址无直接关联。

### 2.3 环境连通性说明

本次任务在**无网络连通 B站接口的环境**下执行，无法实际调用搜索接口获取真实候选视频列表。因此：

- 无法产出真实的候选视频标题、链接、播放量数据；
- 无法执行评论采集，无法产出 raw/clean/comments/output 的真实数据文件；
- 以下内容为**流程执行方案与产出物结构说明**，实际数据需在可连通环境（或用户提供 BV 号）后补齐。

## 四、用户确认环节（步骤 2）

搜索完成后，向用户展示候选视频列表，并请求确认：

> 已搜索到「鸣潮」综合排序 Top1 候选视频如下：
> - 标题：{标题}

> - 播放量：{播放量}
>
> 请确认是否对该视频执行评论采集？确认后我将采集其热度 Top1 评论。

**在用户明确确认前，不得执行评论采集。**

## 五、评论采集阶段（步骤 3，待用户确认后执行）

### 5.1 执行命令

```bash
venv/Scripts/python.exe research-crawler-skill/scripts/bilibili/bridge.py crawl --url "{用户确认的视频链接}" --comment-order 热度 --top 1 --clean basic
```

### 5.2 采集与清洗规则

评论采集时执行基础清洗（`bridge.py` 的 `basic_clean`）：

1. **去重**：相同 rpid 的评论只保留一条
2. **去空**：评论内容为空的丢弃
3. **去@回复**：以 `@` 或 `回复 @` 开头的回复去除元信息
4. **去纯表情**：仅含单个表情符号（去除 `[xxx]` 后长度 ≤1）的丢弃
5. **规范化空白**：所有换行符替换为空格，合并连续空格/tab，使每条评论为单行

### 5.3 预期产出文件结构

```
output/bilibili/鸣潮/鸣潮_{时间戳}/
├── link/video_links.txt                # 视频链接清单
├── search_result.json                  # 搜索元数据
├── raw/
│   ├── {视频id}.csv                    # 原始评论
│   └── clean/
│       └── {视频id}_clean.csv          # 逐视频清洗CSV（12字段）
├── comments/
│   ├── comments.csv                    # 纯评论CSV（序号+评论内容）
│   └── comments_for_ai.csv             # AI分析输入CSV（本次不做AI分析，可留空）
└── output/
    └── output.csv                      # 全量评论（AI字段留空）
```

## 六、采集后错误检测与清理（步骤 4）

采集完成后必须执行：

```bash
venv/Scripts/python.exe research-crawler-skill/scripts/tools/check_output_errors.py
```

检测两类错误，报告写入 `reports/bilibili/error/output_errors.log`：

1. **output 缺失项目** — 扫描 `output/bilibili/` 下所有游戏会话，找出没有 `output/output.csv` 的失败项目
2. **日志错误记录** — 扫描 `reports/bilibili/program/` 下所有 `.log` 文件，找出包含 `ERROR`/错误/失败/跳过 的记录

检测后向用户发送报告并询问：删除失败项目（`delete_output_errors.py`）或重试采集。
